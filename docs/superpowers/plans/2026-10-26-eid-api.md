# EID API (Piece 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every `/hiv/eid/*` route work on the rebuilt EIDMaster. Each route returns the numbers the legacy EID dashboard showed, except for the deliberate ✱ fixes, and serves every card of the new EID dashboard. Admin-only patient searches are added.

**Architecture:**
- **One rules module.** All counting rules live in `hiv/eid/services/eid_common.py` (modelled on `hiv/vl/services/vl_common.py`). The three service files are rewritten on top of it.
- **One pipeline.** Every controller goes through `run_reporting_endpoint`: authentication, cache, real HTTP status.
- **Proof.** SQL-compilation tests prove the rules. `tools/eid_parity_check.py` compares the legacy API with the new one on real data.

**Tech Stack:** Python 3.12, Flask-RESTful, SQLAlchemy 2 (mssql dialect), pytest.

**Spec:** `docs/superpowers/specs/2026-10-26-eid-dashboard-migration-design.md` (copy of the monorepo spec), §4 (pieces 1a/1b) and Appendices A and B. Read §4 before starting.

**Repo and branch:** `api_openldr_python`.
- Create a worktree from `origin/dev`, branch `feat/eid-api-rewrite`.
- Tasks 1–3 form PR "1a". Tasks 4–8 form PR "1b"; it may be split per page group.
- Both target `dev`. The user merges.

## Global Constraints

- Columns are the **un-prefixed** names of the rebuilt EIDMaster (`AnalysisDateTime`, `RegisteredDateTime`, `RequestingProvinceName`, …). No `Result*`-prefixed column may appear in any EID query.
- **Parity principle:** each rewritten route reproduces the rule of the legacy route it replaces (spec Appendix A gives the mapping; the legacy code in `openldr-api/src/modules/eid/` is the reference). That covers its date column, tested/rejected/pending rules and exclusions. Only ✱1–✱7 (spec §4.4) may differ.
- ✱5: every date window is inclusive of the end day (`date_between_inclusive` from `hiv/vl/services/vl_common.py`).
- ✱7: results come from **`FinalResult`** only, for both conventional and PoC.
- Response keys are snake_case, as listed in spec §4.3. Monthly rows carry `year, month, month_name`.
- Errors go through `run_reporting_endpoint`. Exception text never reaches a response.
- Patients routes are Admin-only, use bound parameters only, and allow `per_page` ≤ 500. Contacts (caregiver phone, mother's PTV identifiers) are returned, but never logged.
- Tests run with `python -m pytest -q`, with no database. Never open `.env` or `configs/configs.ini`.
- Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A province name with accents or different case** ("Zambézia" vs "Zambezia") passed as `province[]` must match the stored value the way VL does. It must not silently return no rows (Task 2 test `test_location_filter_matches_vl_normalisation`).
2. **`lab_type` or `category` outside the allowed values** (`lab_type=foo`, `category=9`) must return 400, not 500 or an unfiltered result (Task 2).
3. **A window with no rows** must return `[]` with HTTP 200 on every route, never a 500 from dividing by zero in `positivity` (Task 4 `test_positivity_is_zero_when_no_tested`).
4. **`disaggregation=True` with no province** must group by district nationwide, as the legacy did. It must not crash on a `None` group value (Task 6).
5. **The default 12-month request with `lab_type=all`** must hit the cache key used by the seeds exactly (Task 8 `test_eid_seed_keys_are_cacheable`).

  - `tested_condition()`: `AnalysisDateTime IS NOT NULL`.
  - `rejected_condition()`: `LIMSRejectionCode` or `LIMSRejectionDesc` non-empty.
  - `pending_condition()`: not rejected AND `FinalResult` empty. Values the legacy treated as pending stay pending if they appear in `FinalResult`.
  - `REJECTION_REASONS: list[tuple[str, list[str]]]`: the 8 coded buckets in spec §4.2 order. `rejection_reason_counts() -> list` gives 9 labelled counts, the 9th being `other`.
  - `TAT_SEGMENTS: list[tuple[str, Column, Column]]`: the 6 keys of spec §4.2 with their start and end columns. `tat_filters() -> list`. `tat_averages(zero_as_one: bool) -> list`.
  - `tat_bracket_counts(category: int) -> list` with labels `lt_7, between_7_15, between_16_21, gt_21, no_dates`.
  - `EQUIPMENT_GROUPS: list[tuple[str, list[str]]]`. `equipment_counts() -> list` gives `tested` + 7 groups. `equipment_filters() -> list`.
  - `location_filters(params, exclude_null_province=True) -> list`.
  - `group_column(params, level: str)`: `level` is `"requesting"` or `"lab"`. It follows `facility_type`/`disaggregation` the way VL's facility services do.
